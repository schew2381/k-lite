# Internet clusters ride an overlay, not port maps

ADR 0034 named mutual reachability as the data plane's precondition: every node dialable at `advertise:ingress-slice` by every other node. Across the open internet that precondition fails per network. Each node's router needs forwarding rules, and carrier-grade NAT (LTE, many residential ISPs) offers no inbound at all. The decision is an overlay network, a Tailscale tailnet by default, with no change to k-lite's own code. Machines join the tailnet, every address in play (the address agents dial, `--url`, `--advertise-address`) becomes a tailnet IP, and the join, cert, EDS, and mTLS-ingress paths run exactly as on a LAN. This was verified against the chain, not assumed. The agent accepts any literal non-loopback IP (`internal/agent/advertise.go:23`) and klited's screen rejects only loopback and unspecified (`internal/server/agent.go:393`). The consuming Envoy pins no SANs on the ingress hop (`internal/xds/builder.go:426`), and the donor publishes the ingress slice on `0.0.0.0` (`internal/agent/infrapod.go:202`). What shipped is glue at the edges: `join.sh` grew a `KLITE_VPN=tailscale` mode, `klite node add` prints it when the join URL is a tailnet address, and `docs/real-nodes.md` records every path.

## Considered Options

1. **Port forwarding plus dynamic DNS.** The instinctive answer, and the control plane's half is genuinely cheap (one tcp/7443 forward, since agents dial out per ADR 0004). The data plane's half is not: a router rule and a stable address per node's network, and no answer whatsoever behind CGNAT. Kept as a documented raw path for the all-static-IP case, rejected as the recommendation.
2. **A Tailscale tailnet** (chosen). Both ends dial out, and DERP relays carry the traffic NAT traversal can't, so joining works from networks where forwarding is impossible. It costs zero k-lite code changes and one command per machine, and k3s ships the same integration shape (`--vpn-auth`, their `pkg/vpn`). Costs an account and a third party in the coordination path.
3. **Self-hosted headscale.** Drops the account, keeps the tailnet mechanics, but the coordinator itself must sit on a public IP behind HTTPS (headscale's stated requirements), which is exactly the resource whose absence motivates this ADR. Right for whoever already runs a VPS, wrong as the default.
4. **Single-hub WireGuard.** The cost is one udp/51820 forward on the hub's router, with no account and no third party involved. The recipe in `docs/real-nodes.md` is config-complete. Spoke-to-spoke traffic hairpins through the hub, keys move by hand, and one network still has to be forwardable. Recorded as the no-account variant, not the default.
5. **Native reverse tunneling.** The rathole/frp shape, where NATed machines dial out to a relay that exposes them, fits k-lite's topology (klited is already everyone's dial target, the lighthouse seat `research/overlay-wan.md` noted). A native version would erase the third-party dependency entirely. It's also a relay in the data path, the thing ADR 0034 refused, plus an entire subsystem to build. Recorded as the future option.
6. **IPv6 end to end.** No NAT means no traversal problem. The chain takes literal v6 addresses on paper, but no cluster has run it, join.sh's detection is v4-only, and v6-everywhere is not this decade's residential reality. It stays a raw path nobody has exercised.

## Consequences

- A third party sits in the coordination path, never the mTLS trust path (the cluster CA still signs everything). Tailnet auth keys expire within 90 days, node keys within 180 by default, and an expired node key looks exactly like a dead network: disable key expiry for cluster machines in the admin console.
- Cross-node traffic is encrypted twice, ADR 0034's mTLS inside the tunnel's WireGuard. That's the price of not teaching k-lite about the overlay. The redundancy also means an overlay misconfiguration never downgrades the cluster's own authentication.
- `join.sh` treats 100.64.0.0/10 three ways on purpose. Detection refuses it, since an address only tailnet peers can dial must never be a silent guess. Explicit values pass, and `KLITE_VPN=tailscale` derives one deliberately. A tailnet-shaped `KLITE_URL` with no advertise refuses *before* detection can answer with a public IP no peer dials, the silent blackhole `research/overlay-wan.md:39` predicted. `hack/test-join.sh` pins the range boundaries and the refusals.
- klited's serving cert covers the tailnet address only if tailscaled was up when the cert minted (`sanHosts` walks interfaces at boot, `cmd/klited/main.go:176`). Install order matters once: tailscale first, then restart klited. The failure when it's skipped is the known x509-mismatch loop, documented with its symptom.
- Mixed clusters inherit a rule instead of a fix: every node advertises its tailnet IP, the Mac's local agents included, or Mac-hosted endpoints stay unreachable from the real nodes. Tailscale's LAN-endpoint discovery keeps same-network peers on the direct local path, which is what makes tailnet-IPs-everywhere safe to state as a rule.
- MagicDNS names stay out of the documented path. EDS carries literal IPs, the cert needs `--tls-san` for names, and raw `100.x` addresses are stable anyway.
- Options 4 and 5 are recorded destinations, not dead ends: the hub recipe is runnable today from the doc, and a native tunnel supersedes this ADR if it's ever built.
